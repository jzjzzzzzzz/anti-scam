# Security

This is a small educational prototype, not a security certification or a
multi-tenant production service. Review it before deployment.

- Keep the admin API protected by Cognito JWT validation and the `operators` group.
- Admin access uses PKCE; browser session tokens remain sensitive. Do not expose
  an unauthenticated admin endpoint or publish local demo/bridge listeners.
- Store the Resend key in AWS Secrets Manager and grant only the worker access.
- Add and enable only approved recipients; disabling a recipient blocks subsequent
  work but cannot recall an email already in flight or delivered.
- Initial-send and reminder state transitions prevent ordinary duplicate sends.
  Delivery can be ambiguous after a timeout; inspect uncertain states before retrying.
- HTML bodies are escaped and generated server-side; displayed link labels point
  to the actual exercise endpoint. The text alternative contains the full URL.
- Do not treat the tracking endpoint as an identity check. It intentionally accepts
  unauthenticated bearer links, including requests generated by scanners.
- Dashboard scans are bounded and not a scalable reporting/export subsystem.
- Keep `.env`, AWS files, tokens, logs, SQLite files, captured messages and runtime
  archives out of Git. Run `python3 scripts/check_public.py` before publication.
- Software updates, dependency audits, resource limits, costs, data retention and
  narrow organizational mail rules remain the deployer's responsibility.

Report vulnerabilities through a private GitHub security advisory when enabled.
Otherwise open an issue requesting a private reporting channel without including
secrets, live URLs, recipient records or exploit details affecting an active service.
